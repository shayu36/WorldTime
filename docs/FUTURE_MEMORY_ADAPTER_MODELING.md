# Future Memory Adapter (1s / 2s / 3s)

This document describes the independent future-memory correction path added to
SparseWorld trajectory prediction.  It is a code-level modeling note, not a
performance report.  The implementation has not been formally trained or
evaluated with NuScenes after this change, so no IoU or mIoU improvement is
claimed here.

## Motivation and topology

The old future-memory path accumulated corrected classification logits across
future steps and used a legacy `MemoryConditionedRefiner` topology.  That makes
the absolute class decision at a later horizon depend on an earlier *corrected*
decision rather than on that horizon's own Baseline query.  It also allows an
output-only correction to alter the recurrent state.  The repaired path keeps
these concerns separate:

```text
Baseline state stream:
  Q_base(t), P_base(t) -> OPUS future recurrence -> Q_base(t+1), P_base(t+1)

Output correction stream:
  Q_base(t), P_base(t), S_base(t), fixed Memory, horizon(t)
      -> FutureMemoryAdapter
      -> corrected output for t only
```

For every internal future step, the Baseline first computes its own absolute
classification result:

```text
S_base(t) = ClsBranch(Q_base(t))
```

For target horizons only, the adapter then returns semantic, occupancy and
point residuals plus a reliability gate:

```text
S_final(t) = S_base(t) + G(t) * (DeltaS_memory(t) + DeltaO_memory(t))
P_final(t) = RefinePoints(P_base(t), G(t) * DeltaP_memory(t))
```

`DeltaO_memory` is a point-wise occupancy-confidence logit residual and is
broadcast over the semantic class dimension.  `G(t)` is zero when no valid
candidate is available, so the output is then exactly the Baseline output.
Neither corrected logits, corrected query features nor corrected points are
written back into the Baseline recurrence.  In particular, there is no
`previous_final_logits + current_logits` operation.

## Horizon mapping

OPUS uses six internal future steps at 0.5-second intervals.  The evaluator
keys and adapter selection are:

| Internal step | Horizon | Evaluator output key | Adapter |
|---:|---:|---|:---:|
| 1 | 0.5s | `semantic_occ_1s` | no |
| 2 | 1.0s | `semantic_occ_2s` | yes (`horizon_id=0`) |
| 3 | 1.5s | `semantic_occ_3s` | no |
| 4 | 2.0s | `semantic_occ_4s` | yes (`horizon_id=1`) |
| 5 | 2.5s | `semantic_occ_5s` | no |
| 6 | 3.0s | `semantic_occ_6s` | yes (`horizon_id=2`) |

The 0s observation output and loss remain on the original Baseline path.
Non-target future steps are also unchanged.  The target horizon tuple is
validated to be exactly `(1.0, 2.0, 3.0)` in the dedicated configuration.

## Active-query coverage

At each target horizon the adapter receives every query that is active in the
corresponding Baseline output, including observation queries and all scheduled
future query groups.  With the default schedule (720 observation queries and
scheduled groups `[60, 60, 60, 60, 40, 40]`) the expected counts are:

| Target horizon | Internal step | Active queries passed to adapter |
|---:|---:|---:|
| 1s | 2 | 840 |
| 2s | 4 | 960 |
| 3s | 6 | 1040 |

The implementation obtains these counts from the actual query/stamp tensors;
the values above are assertions for the default scheduling fixture, not
hard-coded limits inside the adapter.

## Memory inputs and candidate score

The fixed-memory loader now carries the schema-v2 semantic distribution along
with feature, metric-frame position, label, reliability and age.  Schema-v1
records receive a uniform semantic prior and retain their label when present;
missing required fields or invalid shapes/ranges raise explicit exceptions.
The fixed cache is read-only and is not regenerated by this change.

Before retrieval, cache points are transformed from their source ego frame to
the current ego frame with the existing pose aligner.  Query and memory points
therefore share a coordinate system for the distance/support terms.

For query `q` and memory item `m`, the attention score combines:

```text
feature similarity
+ log semantic compatibility(query distribution, cached distribution)
- relative-distance penalty
- temporal-age penalty
+ log reliability
```

The cached semantic distribution is also projected into the value stream.  A
valid cached label contributes a small one-hot semantic prior; when no
distribution exists, the label is the one-hot fallback (or a uniform prior for
an unknown legacy label).  Candidate validity additionally checks the cache
valid bit, positive finite reliability, positive age, maximum age and spatial
radius.  Diagnostics expose candidate count, support reliability, age and
distance.

The current query semantic distribution is the mean over point-wise softmax
probabilities of `S_base(t)`:

```text
p_query = normalize(mean_points(softmax(S_base(t))))
```

It is used both in query construction and semantic compatibility, using the
same class-axis convention as the cached distribution.

## Horizon-conditioned adapter

The learned horizon embedding is added before attention:

```text
Q_memory(t) = W_q(
    LayerNorm(Q_base(t))
    + E_horizon(t)
    + W_sem(p_query(t)))
```

Thus changing the horizon id changes the attention query and candidate scores,
not merely a post-retrieval output head.  The adapter then consumes
`[Q_base, Context, Q_base - Context, E_horizon, SupportDiagnostics]` and
produces `DeltaS_memory`, `DeltaO_memory`, `DeltaP_memory` and `G`.

## Initialization and trainability

The original Baseline model is frozen in the dedicated future-adapter mode.
The auditable trainable whitelist is the single prefix:

```text
future_memory_adapter.*
```

This includes attention q/k/v and output projections, semantic projections,
horizon embedding, adapter normalization/MLP, gate, and semantic/occupancy/
position residual heads.  Backbone, neck, OPUS/SparseWorld heads, query
encoding, recurrence and original prediction branches are frozen.  Frozen
modules are kept in evaluation mode to avoid BatchNorm/Dropout drift.

Attention and memory projections use normal Xavier/non-zero initialization.
The gate bias is `-1` (initial sigmoid approximately 0.27).  The final linear
layer of each residual head is initialized to zero, so the initial adapter
output is exactly Baseline-equivalent while those residual heads can receive a
first-step gradient.  There is no tiny global Memory scale such as the old
`alpha=1e-3`.

Training loss wiring uses the existing future semantic/point matching losses
only for corrected target outputs, with unambiguous names:

```text
mem_1s.loss_cls, mem_1s.loss_pts
mem_2s.loss_cls, mem_2s.loss_pts
mem_3s.loss_cls, mem_3s.loss_pts
```

No Memory loss is added for 0s or for non-target intermediate steps.

## Verification scope and limitations

The completed checks cover static compilation, configuration parsing, model
construction, frozen/trainable parameter auditing, cache schema validation,
synthetic identity/no-candidate behavior, horizon conditioning, memory-field
causality, active-query counts, corrected-state isolation and two-step
synthetic backward flow.  Existing query-memory and evaluation tests are also
run.

This phase intentionally stops at code-level acceptance.  It does **not** run
Baseline again, launch formal Memory training, regenerate the fixed cache, or
execute a complete NuScenes validation.  Consequently, the current code cannot
claim an IoU/mIoU improvement; that conclusion requires a later controlled
training and evaluation experiment.
